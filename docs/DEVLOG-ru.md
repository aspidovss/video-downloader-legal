# Video Downloader Legal (VDL)

Расширение для Firefox (в том числе Firefox для Android), Chrome и Microsoft Edge (Manifest V3): находит видео на странице и сохраняет его.
Автор: AspidovSS · Лицензия: MIT · Текущая версия: 1.6.7

## Что умеет

| Возможность | Статус |
|---|---|
| Прямые файлы (mp4, webm, mp3 и др.) через перехват сетевых ответов | работает |
| HLS (m3u8): выбор качества, отдельная звуковая дорожка, AES-128, fMP4, byte-range; TS сохраняется как MP4 без перекодирования | работает |
| DASH (mpd): SegmentTemplate / SegmentTimeline / SegmentList / одиночный файл; видео и звук склеиваются в один файл без перекодирования | работает |

| Instagram (reels, посты, истории) и Facebook: чтение данных страницы, склейка видео со звуком | best-effort |
| X / Twitter: HLS + GIF, в ленте показываются только видео на экране | best-effort |
| Bilibili (.com и .tv) через публичный API сайта, Canva (`/watch`), TikTok (видео на экране) | best-effort |

| История, шаблон имени файла, уведомления, горячие клавиши | работает (на Android нет горячих клавиш и уведомлений) |
| Горячие клавиши: открыть окно, скачать первое видео, скачать аудио первого медиа; в Firefox настраиваются на странице настроек | работает (на Android нет) |
| Боковая панель с кнопкой переключения в окне и в настройках | только Firefox для компьютера |
| YouTube: основной способ через мобильные клиенты (ANDROID_VR/IOS), склейка в один файл; запасной способ запись при воспроизведении (видео и звук склеиваются в webm, mp4 или mkv для VP9+AAC и AV1+Opus), запись прямых эфиров | **работает (проверено на живом YouTube); best-effort: YouTube часто меняется, способ может перестать работать** |
| Только аудио: M4A/WEBM без перекодирования и MP3 (кодировщик lamejs, собирается из исходников скриптом `scripts/build-lamejs.mjs`) | работает |

Без Native Messaging, без внешних серверов, без телеметрии (`data_collection_permissions: none`).

## Установка

**Firefox (компьютер)**
0. **Из каталога Mozilla (обычным пользователям):** https://addons.mozilla.org/en-US/firefox/addon/video-downloader-legal/
1. **Быстрая проверка:** `about:debugging#/runtime/this-firefox` -> «Загрузить временное дополнение» -> выбрать `manifest.json`. Слетает после перезапуска Firefox.
2. **Постоянная установка (рекомендуется):** подписать как *unlisted* на addons.mozilla.org (бесплатно), получить `.xpi` и открыть его в Firefox.
3. **Developer Edition / Nightly / ESR:** в `about:config` поставить `xpinstall.signatures.required = false`, затем открыть `.xpi`. В обычном релизном Firefox это не работает.

Firefox MV3 не выдаёт доступ к сайтам автоматически: после установки откройте `about:addons` -> расширение -> «Разрешения» и включите доступ ко всем сайтам. Минимальная версия: Firefox 140.

**Chrome и Microsoft Edge:** `node scripts/build-chrome.mjs` (или `npm run build:chrome` / `npm run build:edge` для zip) -> `chrome://extensions` или `edge://extensions` -> режим разработчика -> «Загрузить распакованное» -> папка `build/chrome`. Нужны Chrome или Edge 116+. Edge запускает пакет Chrome без изменений.

**Firefox для Android (142+):** обычный `.xpi` без подписи не ставится. Для проверки: отладка по USB, затем `npx web-ext run --source-dir <распакованный пакет> --target firefox-android --android-device <id> --firefox-apk org.mozilla.firefox`. Постоянная установка — из каталога AMO после публикации.

## YouTube: как это работает и чем рискует

**Основной способ (с 1.4.0).** Расширение само спрашивает у YouTube данные видео, но от имени клиентов приложений `IOS`, `IOS_VDL` (дополнительный профиль iPhone), `VISIONOS`, `ANDROID_VR` (запрос к `/youtubei/v1/player`). Эти клиенты отдают обычные ссылки на потоки без SABR. Данные клиентов — публичные идентификаторы мобильных приложений YouTube. Ссылки качаются кусками по 5 МБ. Видео и звук после загрузки **склеиваются в один файл** без перекодирования. Запросы к YouTube из расширения идут с User-Agent этого клиента (через `webRequestBlocking`, только для запросов самого расширения, страницы не затрагиваются).

- **Проверка перед выбором клиента.** YouTube отдаёт `IOS` и `ANDROID_VR` ссылки, которые обрываются с 403 после ~20 МБ (нет токена PO). Поэтому для каждого клиента расширение запрашивает по одному байту в начале, на 10/20/30 МБ и в конце файла. Клиент с оборванными ссылками пропускается. Если оборваны все, варианты крупнее лимита помечаются «>20 MB» и не качаются, остальные доступны.
- **Что работает на практике (проверено пользователем).** Без входа YouTube отвечает `VISIONOS` и `ANDROID_VR` «Sign in to confirm you're not a bot»; `IOS` 21.x отдаёт только SABR. `IOS` 20.x отдаёт ссылки, которые обрываются после ~20 МБ: аудио и короткие ролики качаются напрямую, длинные видео надо записывать (кнопка записи).
- Клиенты и их порядок задаются в настройках; там же можно добавить свой клиент в JSON. Версии и User-Agent устаревают, поэтому в настройках есть JSON-переопределения: если YouTube перестал отвечать, обновите версию без обновления расширения.
- Параметр `n` и токен PO **не вычисляются и не подделываются**. Если YouTube откажет (HTTP 403), расширение скажет об этом и предложит запасной способ.
- Без куки: мобильные клиенты их не используют. Видео с возрастным ограничением и приватные берите записью.
- Диагностика (кнопка «Скопировать диагностику YouTube») показывает по каждому клиенту HTTP-статус, статус воспроизведения, число форматов и **имена** параметров ссылки без значений.

**Запасной способ** описан ниже: запись при воспроизведении.

Что нужно знать:
- Это нарушает условия YouTube, если нет разрешения правообладателя. Ответственность на вас.
- **Проверено на живом YouTube, работает.** Но YouTube часто меняется, и позже способ может перестать работать: сломаться могут версии клиентов, требования к токенам и заголовкам. Пришлите диагностику, если способ не сработает.
- Настройка «YouTube: разрешать только видео Creative Commons» блокирует остальные (лицензия читается из метаданных страницы; если не удалось определить, видео считается не-CC).

### YouTube: режим «Записать при воспроизведении» (v1.3.0)

Диагностика на Firefox 158 показала, что плеер ходит только через SABR (POST-запросы, прямых ссылок нет), поэтому скачать форматы по ссылкам нельзя. Вместо этого расширение умеет **записать то, что плеер сам скачал и отдал в `MediaSource`**:

1. Откройте видео, в окне расширения нажмите «Записать при воспроизведении». Страница перезагрузится, видео проиграется целиком без звука на ускорении (настройка «скорость записи», по умолчанию 2x; Firefox ограничивает примерно 5x).
2. Не закрывайте вкладку, пока идёт запись. Качество выбирает сам плеер.
3. Когда запись готова, нажмите «Сохранить файл»: видео и аудио склеиваются в **один файл** без перекодирования (webm+weba в webm, mp4+m4a в mp4; VP9+AAC и AV1+Opus в mkv, с 1.5.1debug15 и 1.6.0dev1). Если склейка не удалась, сохраняются два файла (аудио с суффиксом `.audio`). Кнопка «Только аудио» сохраняет отдельно звуковую дорожку (`.weba` или `.m4a`).

Ограничения: DRM-контент отклоняется; реклама отбрасывается; лимит размера берётся из «макс. размер потока»; данные хранятся в памяти вкладки. Проверено на живом YouTube, работает; но YouTube меняется, и позже запись может перестать работать. Если не сработало, пришлите диагностику.


## Ограничения (честно)

- HLS/DASH собираются в памяти браузера и отдаются как один файл; лимит по умолчанию 4096 МБ (настраивается). На телефоне памяти меньше, длинные потоки могут не поместиться.
- Видео и звук одного контейнера склеиваются без перекодирования (DASH, HLS с отдельным звуком, запись YouTube). Если склейка невозможна, сохраняются два файла: `имя.ext` и `имя.audio.ext`. Прямое скачивание YouTube подбирает звук того же контейнера; смешанные контейнеры склеивает только запись из плеера (VP9+AAC и AV1+Opus в mkv).
- HLS в формате TS конвертируется в MP4 без перекодирования, если кодеки H.264 + AAC и файл не больше ~700 МБ; иначе сохраняется `.ts`.
- В DASH берётся только первый Period.
- Сайтам с особыми заголовками расширение подставляет `Referer`/`Origin` только для известных адресов (YouTube, TikTok, Bilibili, живой HLS) правилами заголовков; для остальных возможен 403.
- Firefox для Android: нет контекстного меню, горячих клавиш, уведомлений и боковой панели, нет кнопок «Открыть папку»; на реальном телефоне функционал на момент 1.6.0dev2 ещё не проверен автором.
- Поддержка сайтов проверена на живых страницах (Firefox, Chrome, Edge), но сайты меняются, и поддержка может перестать работать; в таком случае пришлите диагностику.
- DRM-контент не поддерживается и не обходится.

## Правовая сторона

Сохраняйте только то, что вам разрешено сохранять. Соблюдение правил сайтов - ваша ответственность.

- **1.6.0dev6.** Склейки разных контейнеров пишутся в обычный MP4 (`writeMp4` в `lib/mux.js`: moov в начале, чанки по ~0,5 с; Opus в MP4 — `Opus` + `dOps` из OpusHead, длительности пакетов по TOC; VP9 из WebM — `vp09` + `vpcC` из заголовка ключевого кадра; AV1 из WebM — `av01` + `av1C`). Причина: тест в Telegram Desktop 17.10 — любые MP4 и WEBM уходят как видео, MKV — документом; запись «The Wait» в MP4 автор проверил: видео, звук, перемотка. MKV — настройка `joinFormat`. Лимит «Игнорировать файлы меньше» снова 150 КБ (однократная миграция с 10). Ссылка на AMO в README, журнале и справке. 240 тестов.
- **1.6.0dev5.** Субтитры YouTube (`lib/subs.js`: список дорожек из ответов API-клиентов и страницы, timedtext json3 → SRT, перевод YouTube на язык интерфейса; дорожка D_WEBVTT/SUBTITLES внутри .webm, иначе .srt рядом). Причины недоступности YouTube (`lib/ytverdict.js`: сначала коды статуса, потом текст причины на en/ru) и поле `verdict` в диагностике. Значок CC BY. Склейка .webm с оглавлением, потоково по кластерам. Удалено контекстное меню (и разрешение `contextMenus`). Блок диагностики: ✕, привязка к странице, кнопки не прыгают. Сборщик для AMO `scripts/build-amo-dev.mjs`. Субтитры на живом YouTube в этой среде проверить нельзя (нет доступа к сайту) — проверяет автор.
- **1.6.0dev4.** Склеенные .mkv (AV1/H.264 + Opus, VP9 + AAC) пишутся общим модулем `writeMkv` в `lib/mux.js`: известный размер Segment, SeekHead, оглавление Cues по кластерам с ключевыми кадрами, видео и звук в одних кластерах (новый кластер — на ключевом кадре не реже чем раз в 5 с). Раньше звук шёл отдельными 10-секундными кластерами, и после перемотки он мог появляться с задержкой. Проверено на записи пользователя (AV1 1280×720 + Opus, 60 с): перемотка на 45 с читает 230 КБ вместо 3,5 МБ, все 1440 кадров и 3000 пакетов звука на месте. 210 тестов.

## Инструменты для тестов
- `ffmpeg`/`ffprobe` нужны только тестам (`tests/*.test.js` создают из них проверочные файлы). В пакет расширения они не входят, с кодом не связаны и не распространяются, поэтому в `LICENSE`/`THIRD-PARTY.md` не указываются. Это внешний инструмент разработчика (лицензия LGPL/GPL зависит от его сборки).

## Открытые вопросы и заметки на будущее
- **Android:** проверить на реальном телефоне (установка, скачивание, HLS, MP3, скрытые элементы интерфейса).
- **Chrome / Edge:** боковая панель через `sidePanel` — пока не делаем.
- **Плееры:** для AV1 проигрывателю Windows может понадобиться «Расширение для видео AV1» из Microsoft Store.
- **Субтитры:** проверены тестами; на живом YouTube их проверяет автор (timedtext может требовать токен плеера — тогда помогает включить субтитры в плеере на пару секунд).
